# M7 阶段演示录屏指南

本文用于完成阶段任务 5：录制一个约 3 分钟的 M7 检索、证据问答与视觉故事演示。

## 1. 当前系统的录屏能力

当前机器是 Ubuntu 24.04、GNOME 桌面、X11 会话。GNOME 已内置录屏，因此不需要安装 OBS 或其他软件。

启动方式：

1. 按 `Print Screen` 打开截图工具。
2. 点击工具栏中的摄像机图标，切换为录像模式。
3. 选择全屏或矩形区域。建议只框选浏览器和必要的终端区域。
4. 点击红色录像按钮开始。
5. 结束时点击顶部状态栏的红色录制指示器。

录像默认保存在 `/home/tiantiantianyi/Videos`，部分 GNOME 版本会放入其 `Screencasts` 子目录。

## 2. 录制前准备

进入仓库并启动环境：

```bash
cd /home/tiantiantianyi/Desktop/nlp/nlp_courcedes
conda activate vlm-course
```

启动当前真实 M7 页面：

```bash
env -u ALL_PROXY -u all_proxy \
  python scripts/launch_app.py \
  --config configs/benchmark_8gb.yaml \
  --split val --port 7861
```

浏览器打开：

```text
http://127.0.0.1:7861
```

正式录制前先做一次预热：

1. 搜索“雨夜城市街道”。
2. 选择一张图片，问“第一张图片中能直接确认什么？”。
3. 等待 Qwen-VL 完成首次加载。
4. 确认页面没有报错后再开始录像。

预热可以避免录像的大部分时间消耗在模型冷启动上。不要关闭服务；回到页面重新搜索即可开始正式演示。

## 3. 推荐的三分钟脚本

### 0:00–0:20：说明项目和运行模式

建议口播：

> 这是 AskAlbum 的阶段性演示。当前在 RTX 4060 Laptop 8GB 上运行，使用 Chinese-CLIP 做图像召回，并用 Qwen3-VL 做候选重排和证据问答。当前演示使用 image-only 索引，正式标注冻结后会切换到 image、text 和 BM25 三路检索。

画面展示页面标题和 GPU/模型说明即可，不要长时间展示代码。

### 0:20–0:55：图文检索

1. 输入查询“雨夜城市街道”。
2. 保持视觉重排关闭，先展示 Chinese-CLIP 的召回结果。
3. 简要指出图片 ID、分支分数和结果图片。

建议口播：

> 即使正式结构化标注还没有到达，系统也能直接用原图构建 Chinese-CLIP 索引，因此检索界面和后续 Agent 可以并行开发。

### 0:55–1:45：带引用的证据问答

1. 打开“视觉故事 · M7”页。
2. 选择 1–3 张检索结果。
3. 输入“第一张图片中能直接确认什么？”。
4. 展示回答中的 `[img_val-xxxx]` 引用、置信度和逐图证据。

建议口播：

> 回答只能引用本次选择的图片。无法从画面确认的地点、人物身份等信息会保留不确定性；证据不足时系统会明确拒答，而不是编造答案。

如果想展示拒答，可以再问：

```text
这些照片拍摄于哪个具体城市和哪一天？
```

### 1:45–2:35：视觉故事

1. 回到搜索页换一个能得到多张结果的查询，例如“城市夜景”或“户外旅行”。
2. 在 M7 页面选择 3–8 张图片。
3. 填写主题与语气；首次演示先不勾选补图，点击“自动编排视觉故事”。
4. 展示自动排序说明、分段标题、缺图占位和故事影像序列。
5. 若需要演示生成，再勾选“自动检测并补全缺图”；生成图会显示“✨ AI 生成”。

建议口播：

> 视觉故事共享检索结果，并为每个叙事段落保留图片来源。后续若启用缺图补全，生成图片会明确标记为 AI 生成，避免与真实照片混淆。

### 2:35–3:00：阶段结论

建议口播：

> 当前已经完成 M7 真实界面、证据引用与拒答机制，并在 8GB 显存上完成真实运行。M6 多查询基准峰值约 4.04 GiB。标注冻结后将重建三路索引，并用人工 relevance 运行 A5 和 A6 正式质量评测。

最后在页面上停留 2–3 秒再停止录像，方便后期剪辑。

## 4. 画面和声音设置

- 分辨率优先使用 1920×1080；如果字体太小，把浏览器缩放调到 110%–125%。
- 关闭消息通知、聊天窗口和可能显示隐私信息的终端标签页。
- 浏览器只保留演示页面，避免露出 GitHub token、代理配置或本地私人目录。
- GNOME 内置录屏通常只录画面。需要口播时，可用手机单独录音后合成，或改用 OBS 录制麦克风。
- 如果现场模型响应较慢，可以保留短暂等待，但不要剪接成“瞬时返回”；报告应如实说明冷启动与热启动差异。

## 5. 录完后的检查

至少完整播放一次，确认：

- 视频能打开，画面无黑屏。
- 查询、候选图片和引用清晰可见。
- 没有把 image-only 结果称为正式三路检索结果。
- 没有把 M6 的模型自评分称为 MRR 或 nDCG。
- 没有暴露密码、密钥、个人通知或无关文件。
- 总时长建议控制在 2 分 30 秒到 3 分 30 秒。

建议文件名：

```text
AskAlbum_M7_Stage_Demo_2026-08-10.webm
```

若课程平台只接受 MP4，可使用系统已有的 FFmpeg 转换；当前系统未检测到 FFmpeg 时再安装即可，不影响直接提交 WebM。
