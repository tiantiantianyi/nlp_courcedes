# 忆见 AskAlbum 最终 Demo 操作手册

本文固定演示环境、五类查询、智能排序/视觉故事操作顺序和三分钟录屏节奏。查询来自 `evaluation/formal_val_100/queries.jsonl` 中已审核的正式 100 条集合，并复制到 `configs/final_demo_queries.jsonl`。`expected_source_image_id` 只用于现场核对来源正例是否出现，不等价于候选级人工 qrels，也不能单独证明最终 Recall、MRR 或 nDCG。

## 1. 演示边界

最终 Demo 覆盖：M3 三路索引读取、M4 五类查询理解、M5 融合结果、M6 可选视觉重排，以及 M7 引用问答、拒答、3--8 图自动排序、缺图补全与 AI 标识。M0--M2 不在张添翼的个人演示归属范围内；M3--M5 应表述为“在队友代码基础上完成迁移、接口打通与验证”。

演示结果是一次可复现运行记录。正式候选级 `0/1/2` qrels 已冻结；A5 显示 weighted 三路融合在当前 qrels 上总体最好，A6 显示视觉重排没有超过检索原序，但 Listwise 相比 Pointwise 获得约 4.50 倍总时延加速。上述指标来自正式产物，不从演示画面临时推断。

## 2. 演示前环境检查

在仓库根目录执行。以下命令只读数据、模型、索引与 GPU 状态：

```bash
test -d ../Val
test -f artifacts/indexes/val/annotations.json
test -f artifacts/indexes/val/manifest.json
test -d models/chinese-clip-vit-base-patch16
test -d models/bge-small-zh-v1.5
test -d Qwen--Qwen3-VL-2B-Instruct/snapshots/master
test -d stablediffusion
nvidia-smi
```

检查固定查询 JSONL 可解析、正好五条且五类各一条；该命令只读：

```bash
conda run -n vlm-course python -c \
  "import json,pathlib; p=pathlib.Path(\"configs/final_demo_queries.jsonl\"); rows=[json.loads(x) for x in p.read_text(encoding=\"utf-8\").splitlines() if x.strip()]; assert len(rows)==5; assert {r[\"category\"] for r in rows}=={\"simple\",\"compositional\",\"negative\",\"count\",\"ocr\"}; print(rows)"
```

运行目录流水线 dry-run。它只输出计划，不建索引、不加载模型、不创建工作区：

```bash
conda run -n vlm-course python run.py --input_dir ../Val --dry-run --launch
```

确认 `artifacts/generated/` 可写；该命令只会创建空目录：

```bash
mkdir -p artifacts/generated
```

关闭通知和无关窗口，浏览器缩放设为 110%--125%。不要在录屏中展示 API Key、代理、私人路径或通知。

## 3. 启动与预热

最终录屏使用完整三路配置；该配置已在 RTX 4060 Laptop 8GB 上验证，普通检索默认关闭智能排序：

```bash
env -u ALL_PROXY -u all_proxy \
  conda run --no-capture-output -n vlm-course python scripts/launch_app.py \
  --config configs/default.yaml --split val --host 127.0.0.1 --port 7860
```

访问 <http://127.0.0.1:7860/>。另一个终端执行只读健康检查：

```bash
curl --fail --silent --show-error http://127.0.0.1:7860/ >/dev/null
```

录屏前预热一次：搜索“雨夜城市街道”，勾选“启用智能排序”并执行；随后打开“视觉故事”，选择前三张并提问“这些图片中能直接确认哪些共同场景？”。最后关闭“启用智能排序”。预热会加载模型和产生 CUDA 缓存，但不改索引；不要把预热延迟当作热启动延迟。

## 4. 五类固定检索

依次在“探索相册”输入下表查询。前四个保持“启用智能排序”关闭，组合查询可以额外演示一次开启后的次序变化。每次展开“查看匹配依据”，确认综合匹配、三路依据和匹配线索卡片完整。

| 顺序 | 类别 | Query ID | 查询文本 | 预期来源图 |
|---:|---|---|---|---|
| 1 | 简单 | q007 | 长颈鹿进食 | val-2033 |
| 2 | 组合 | q001 | 一只在窗边趴着的表情严肃的猫 | val-2007 |
| 3 | 否定 | q072 | 没有人物的乡间田野和远山 | val-2340 |
| 4 | 计数 | q082 | 桌上摆着七个烤生蚝 | val-2138 |
| 5 | OCR | q093 | 写有“库仑定律”的物理笔记 | val-2111 |

检索验收：

- 页面返回 1--8 张图片，无 Error 弹窗。
- 预期来源图若出现，记录其可见排名；若未进入 Top-8，如实记录，不临时换查询。
- “查看匹配依据”显示综合匹配分数、画面语义、描述语义、关键词分支及匹配线索。
- 开启“启用智能排序”后，卡片可额外显示智能排序分数；关闭时不显示是正常行为。
- 不把综合匹配分数或智能排序分数解释成人工相关性标签。

## 5. 候选选择与带引用问答

1. 在 q001 或“雨夜城市街道”的结果中打开“视觉故事”。
2. “选择图片”默认勾选前三张；图片问答只保留 1--3 张。
3. 输入有依据问题：“这些图片中能直接确认哪些共同场景或物体？”
4. 点击“生成带引用回答”，展开“查看引用依据”。
5. 确认正文引用只使用当前选中图片，格式为 `[img_val-xxxx]`。

引用依据应显示回答状态、置信度、使用的图片引用，以及每张图片中“可直接确认”和“仍需谨慎”的内容。

随后演示拒答：

```text
请给出这些照片拍摄的准确日期、摄影者姓名和相机序列号。
```

预期 `refused=true`，或回答明确说明证据不足且不编造具体值；`citations` 不得包含未选图片。若模型产生无法核对的具体身份、日期或设备编号，将其记录为失败案例，不要口头包装为正确。

## 6. 视觉故事：先不补图

1. 搜索“雨夜城市街道”，进入“视觉故事”。
2. 在当前候选中选择 5 张；故事允许 3--8 张，超出范围应由页面阻止。
3. 主题填“雨夜城市转场”，语气选“纪实”，“创作编号”保持 `20260802`。
4. 取消“自动检测并补全缺图”，点击“自动编排视觉故事”。
5. 展开“查看故事详情”。

无补图验收：

- “查看故事详情”中的图片顺序与所选 ID 集合一致，允许顺序变化。
- 时间线中的真实图片显示“原始图片”，排序方式以自然语言展示。
- 若识别出缺口，详情卡显示“等待补全”，但尚无生成图片。
- 页面免责声明明确叙事不代表真实地点、身份或事件经过。

## 7. 视觉故事：缺图补全与 AI 标识

保持同一批图片、主题、语气和创作编号，只勾选“自动检测并补全缺图”后再次编排。Qwen 与 Stable Diffusion 会串行切换，8GB 显存下不要同时触发其他重排或生成请求。

已验证的备选案例是查询“雨夜城市街道”，五张候选 `val-2078`、`val-2322`、`val-2044`、`val-2199`、`val-2070`；2026-08-16 本机实跑在 `val-2044` 与 `val-2078` 之间检测到场景转场并完成补图。当前索引排序变化时，只在这五张确实出现在本次结果中时选择它们，不允许把旧产物冒充本次结果。

补图验收：

- 生成成功的过渡卡显示“AI 已补全”，故事影像序列显示“✨ AI 生成”。
- 时间线徽标和“故事影像序列”标题都显示“✨ AI 生成”，原图仍显示“原始图片”。
- 生成文件仅写入 `artifacts/generated/`，不进入 Val 数据集和 Git。
- 生成失败时详情卡显示“补全失败”和原因，原故事仍可查看；不得用原图伪装成生成图。
- 如果本次没有检测到缺口，应如实展示“序列衔接自然”；可改用已验证五图序列再试，但不通过降低阈值伪造演示。

## 8. 三分钟录屏时间线

| 时间 | 画面与操作 | 口播重点 |
|---|---|---|
| 0:00--0:15 | “忆见 AskAlbum”首页 | 本机 4060 Laptop 8GB；智能检索、智能排序、图片问答和视觉故事 |
| 0:15--0:55 | 快速粘贴五类固定查询 | 五类来自审核集合；展示图片 ID 和“查看匹配依据”卡片 |
| 0:55--1:20 | q001 开关“启用智能排序” | 只调整固定候选顺序；页面分数不是人工相关性标签 |
| 1:20--1:50 | 图片问答与拒答 | 引用限定在所选图片；证据不足时不编造 |
| 1:50--2:20 | 5 图故事，不补图 | 3--8 图自动排序、原图来源和免责声明 |
| 2:20--2:50 | 同一故事启用补图 | 生成能力串行运行；生成图醒目标注 AI，不混入原图 |
| 2:50--3:00 | 可读详情与总结 | 展示排序、引用和 AI 来源卡片；简述正式 A5/A6 结论 |

若补图耗时较长，录屏前完成同配置预热，但保留真实等待过程的一部分，不剪辑成“瞬时完成”。总时长建议 2:45--3:30。
