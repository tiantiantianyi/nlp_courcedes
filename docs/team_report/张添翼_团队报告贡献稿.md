### 1.2 M5 融合对照与 M5→M6 契约

在队友已有 RRF 基线上增加分支内 min–max 归一化的 weighted fusion，并保留每路原始分数、名次、融合权重和分支降级信息。随后冻结 `m5-to-m6-v1.0` 契约：每个查询一行、恰好 20 个唯一候选、rank 1–20 连续、branch scores/ranks 键集合一致，并对 manifest、split、候选路径和图片解码做完整扫描。契约错误会阻断 M6，而不是静默修复 M5 输入。

### 1.3 M6 Top-20 listwise 重排

将 M5 Top-20 候选缩放并组合为 contact sheet，通过短编号和白名单提示 Qwen3-VL-2B-Instruct 一次输出完整顺序。系统将重复 ID 去重，将遗漏候选按 M5 原序补到末尾，并在结果中记录 `degraded=true` 与 mismatch；未知 ID、空列表、非法 JSON 或模型异常触发完整 M5 顺序硬回退。该设计区分“部分降级”和“硬失败”，避免页面看似成功却掩盖模型未遵守排序契约。

### 1.4 M6→M7 桥接、自动故事和缺图补全

M7 严格从一个 M6 query 中选择 3–8 张图，并保持候选集合不变。canonical 标注只读映射为故事证据，包括 summary、scene、时间桶、实体、OCR、颜色、情绪和不确定字段。故事规划器按时间桶和场景/实体相似度稳定排序，在跨时段或低相似转场处生成 gap。只有显式启用补图时才加载 Stable Diffusion；生成段落必须同时保存 `source=generated` 和 `ai_generated=true`，确保合成图不会被误认为真实数据集图片。

### 1.5 M4 三后端、A7 与正式评测门禁

M4 增加 rules、local Qwen 和 OpenAI-compatible 三后端：规则层保护否定、数量、OCR 和时间等硬条件，LLM 只补充软语义，失败时记录原因并回退。A7 适配 jina-clip-v2，并定位、修复低内存加载导致 EVA RoPE buffer 未初始化和图像向量 NaN 的问题；输出端增加 NaN/Inf 硬门禁。评测部分整理 100 条来源正例查询和五类均衡的 50 查询候选池，实现候选级 0/1/2 标注页、qrels 完整性验证、A5 五变体和 A6 baseline/pointwise/listwise 接口。人工 qrels 未冻结时程序不允许生成最终质量表。

## 3. 建议放入 Discussion 的反思

1. 生成式重排器必须被视为不可信外部组件。即使模型调用成功，也可能重复、遗漏或输出未知 ID，因此结果契约、白名单和降级审计比单纯调整 prompt 更重要。
2. 8GB 显存设备的核心不是让所有模型同时常驻，而是控制生命周期：检索编码器、Qwen 和 Stable Diffusion 串行加载与卸载，以时延换取可运行性。
3. 工程测试、资源实验和正式质量实验必须分开。20 图、64 图或 q001 source-positive smoke 可以验证链路，却不能证明 RRF、weighted、pointwise 或 listwise 的检索质量提升。
4. 人工相关性标签不能从检索分数自动推断；否则评测会偏向产生候选池的系统。正式指标必须等待候选级 0/1/2 qrels 冻结。
5. M7 生成图必须有可见和结构化的双重 AI 标识；在课程演示中也应把真实检索图片和生成图片分开展示。
