# 人工检索评测页面中文化与来源图 ID 设计

## 目标

降低人工相关性标注的误操作风险，同时保持现有评测数据格式和验证接口兼容。

## 界面行为

- “查询类别”下拉框显示中文标签：简单查询、组合查询、否定查询、数量查询、文字识别查询。
- 下拉框提交和保存的内部值仍分别为 `simple`、`compositional`、`negative`、`count`、`ocr`。
- 在只读 `Query ID` 下方增加只读“来源图 ID”字段；切换任务时与来源图同步更新。
- “来源图 ID”读取任务记录中的 `source_image_id`，例如第 1 条显示 `val-2007`。
- 空白任务的“标注者”默认显示“张添翼”；已保存任务保留其原标注者，不被默认值覆盖。
- 空白任务的“相关性判断”默认显示 `<source_image_id>:2`，例如 `val-2007:2`；已有判断保持原样，不被默认值覆盖。
- 页面不自动勾选审核、不自动保存，也不自动给其他候选图评分；标注者仍需观察图片后人工确认。

## 数据流与兼容性

`load_position` 从任务 JSONL 读取 `source_image_id` 并作为新增页面输出。中文类别只作为 Gradio 下拉框的显示标签，回调收到的仍是英文枚举值，因此 `save_review`、`validate_manual_set`、A5 和 A6 的输入协议不变。已有已保存任务再次打开时能够正确选中对应中文标签。标注者默认值只在任务的已有 `annotator` 为空时用于页面展示，并在用户主动保存时进入现有字段。相关性文本先读取已有 CSV 判断；仅当当前 query 没有判断时，才用来源图 ID 生成一个待人工确认的 2 分默认行。

## 错误处理

- 任务缺少 `source_image_id` 时，让现有加载回调明确失败，不伪造 ID。
- 保存时继续由现有校验拒绝空查询、无效类别、空标注者及缺少 2 分正例的已审核任务。

## 测试与验收

- 单元测试断言五个中文标签与五个英文内部值一一对应。
- 页面加载测试断言返回的来源图 ID 与任务记录一致。
- 页面加载测试断言空标注者默认为“张添翼”，且非空已有标注者不会被覆盖。
- 页面加载测试断言空判断默认为 `val-2007:2`，已有判断不会被默认行覆盖。
- 现有人工评测数据测试继续通过，证明持久化格式未改变。
- 重启本地服务后，通过 Gradio API 加载第 1 条任务，确认显示 `q001`、`val-2007` 和来源图像。

## 非目标

- 不改动人工评测 JSONL/CSV schema。
- 不自动生成查询，不自动给来源图之外的候选图评分。
- 不修改 M3–M7 的检索、重排或故事生成逻辑。
