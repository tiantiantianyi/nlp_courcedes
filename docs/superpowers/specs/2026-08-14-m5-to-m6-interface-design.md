# M5 到 M6 Top-20 接口设计

日期：2026-08-14

状态：设计已经用户逐项确认；仅涵盖 M5 输出到 M6 输入及 M6 侧校验，不修改 M1--M5
实现。

## 1. 目标与范围

建立一个跨进程、可审计、可机器校验的 M5→M6 数据契约。M5 为每个查询导出融合后的
Top-20；M6 在调用 Qwen3-VL 前完成严格校验，并保留 M5 的全部原始排序证据。

正式对外接口文档为 `docs/M5_TO_M6_INTERFACE_V1.md`。

范围内：

- 查询批次式 JSONL；
- 顶层查询元数据和候选字段；
- Top-20、分支证据、路径和图片校验；
- M6 侧读取器、校验器、报告与测试；
- M6 模型输出的可审计降级。

范围外：

- M1 标注生产与清洗；
- M3 索引实现；
- M4 查询解析；
- M5 召回、融合算法与代码；
- 用标注替代人工 relevance judgments；
- M7 以外的系统改造。

## 2. 已确认的设计决策

### 2.1 查询批次式 JSONL

每个查询占一行，一行内包含完整 Top-20。相较候选逐行格式，它避免跨行聚合和顺序恢复；
相较单个 JSON 数组，它支持逐查询错误定位和断点处理。

### 2.2 审计信息必填

每个候选必须携带 `branch_scores` 和 `branch_ranks`。两个字典的键集合必须相同，分支未
召回时同时省略，不能用 0 值伪造缺席分支。

### 2.3 可移植路径

图片使用相对项目根目录的 POSIX 路径。路径解析并消解符号链接后必须位于声明 split 的
配置数据根目录，且应与索引 manifest 一致。

### 2.4 M6 不回写 M5

M6 保持 M5 数组顺序作为原始排序，不按分数重算；只在新输出中增加重排结果和降级信息。
原始 M5 JSONL 始终只读。

## 3. 数据流和组件

```text
M5 exporter（队友负责）
  -> m5_to_m6_candidates.jsonl
  -> M6 contract reader
  -> M6 validator + validation report
  -> SearchResult 转换
  -> pointwise/listwise reranker
  -> m6_reranked_results.jsonl
  -> M7
```

M6 侧计划包含三个边界清晰的组件：

1. 契约模型：只表达 `m5-to-m6-v1.0` 字段和结构约束；
2. 文件校验器：处理跨行唯一性、路径、manifest 和图片解码；
3. M6 导入器：只在校验成功后把候选转换为现有 `SearchResult`，不包含检索逻辑。

## 4. 错误处理

校验器扫描整个文件并收集全部错误，但只要存在一个错误，整批正式 M6 就被阻断。这样既
能一次把完整错误清单反馈给 M5 同学，也不会静默使用部分候选。

进入 Qwen3-VL 后，未知 ID 或无效 JSON 保留 M5 原序；重复 ID 去重；遗漏 ID 按 M5 原序
补尾。所有模型失约都写入 `degraded` 与 `mismatch`，不能伪装为完整重排。

## 5. 测试策略

实现阶段采用测试驱动开发，至少覆盖：

- 一条完整合法 Top-20；
- 19/21 个候选；
- 重复 query ID 和 image ID；
- rank 不连续；
- 分支键不一致或未知；
- NaN/Inf 和非数值分数；
- 绝对路径、反斜杠、split 逃逸、图片缺失和损坏；
- manifest 中不存在的 ID 或路径错配；
- 多行错误一次收集且退出码非零；
- 合法记录到 `SearchResult` 的无损映射；
- M6 重排后 M5 字段保持不变；
- Qwen 输出重复、遗漏和未知 ID 的降级路径。

验收顺序为单元测试、接口文件验证、一条查询 contact-sheet 冒烟、完整 M6 本地性能测试。
没有人工 qrels 时只报告接口、资源和降级证据，不报告排序质量提升。

## 6. 成功标准

- 对外接口文档可直接发给 M5 同学独立实现导出；
- 合法文件能被 M6 逐行读取并保持 M5 排序；
- 所有结构、跨行、路径、图片和 manifest 错误都有稳定错误码；
- 任一接口错误阻断正式 M6；
- M6 输出包含全部输入候选且每个恰好一次；
- 代码变更限定在 M6 读取、校验、测试、脚本和 M6/M7 联调文档，不修改 M1--M5 实现。
